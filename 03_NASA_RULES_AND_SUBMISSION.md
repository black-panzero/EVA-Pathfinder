## 1. Deadline and eligibility (official guide pp. 2, 12)

- Submission opens **Saturday November 14, 2026, 9:00 a.m.** local event time.
- Deadline: **Sunday November 15, 2026, 11:59 p.m.**, time zone of the team's **Local Event**. Universal Event uses Team Owner's residence time zone.
- Click **Submit for Judging**; saving a draft is not submission.
- Team members must be confirmed participants of the same Local Event for awards; verify team membership. The website indicates maximum six participants.
- All required fields must be complete and project submission language must be **English**.
- The guide forbids any image, audio, video, or other likeness of a person under age 18 in project demonstrations or final projects.
- The user/team must individually review and accept organizer terms, originality verification and privacy terms. Agents cannot accept or sign on their behalf.

### Hosting rules (guide pp. 4, 6–7, 10–11)

- The form can embed JPG/PNG/GIF up to **10 MB per image**, but cannot directly upload videos or documents: place those on a publicly readable platform and link.
- URLs must include full `https://` and **must not require login, password, permission request, registration**.
- Test links in an incognito browser and with another device/account.
- Demo 7 slides (including title/intro) **OR** ≤30 seconds video; keep strictly within limit, not a longer narrated walkthrough.
- English on the project page and slide decks; non-English video narration needs English subtitles.
- Both a demo URL and final project URL are required (may be hosted by different platforms).
- Do not invent GitHub URLs, video IDs, deployment links or visibility status. They are not complete until created and independently verified.
- For a newly hosted domain, guide suggests optional FortiGuard classification to improve access, not a substitute for confirming accessibility.

## 3. SI/AI use rules (guide p. 8)

**The uploaded NASA guide explicitly says** SI tools may be used to accelerate building but **should not be used to come up with the team's solution idea**. This packet was prepared with AI-assisted planning. Thus the team must independently validate, develop and take ownership of its real original concept and **cannot represent this handoff as independent human-only work**. A coder agent should help execute a human-owned design, not fabricate originality claims.

Required disclosures from the guide:

- **Images/videos generated by SI:** visible watermark indicating SI generation.
- **Audio generated by SI:** descriptive text and metadata acknowledgement.
- **Code/data generated or substantially assisted by SI:** acknowledgement in descriptive text/metadata (e.g. `docs/SI_DISCLOSURE.md`, module header/NOTICE, generated-data manifest).
- **No SI-generated content containing/using/modifying NASA branding or design elements** such as logos, flags, mission identifiers. Prefer NASA factual imagery accessed directly, with proper credit, and create interface visuals without NASA branding.
- Select all applicable SI categories on the live submission form. `I did not use SI` would be inaccurate if AI assisted planning, code or prose.
- SI disclosures do **not** remove the requirement for human verification of scientific outputs.

**Truthful disclosure template (edit to what actually happened):**

> The team used AI-assisted software to help refine technical documentation, structure implementation tasks, and assist with selected code and testing. Team members selected, reviewed and validated scientific data, algorithms, scenarios, source citations and final results. AI-assisted source code and documentation are identified in repository notices and development records. No AI-generated imagery or audio is included unless explicitly marked as required.

Do not claim the human team independently devised the central method if that is not accurate. Seek team/organizer guidance if uncertain about the guide's idea-origin rule.

## 4. NASA challenge relevance requirements

The user-provided challenge asks for a **layered hyperlocal Mars map** integrating NASA mission data at the scale of a Marswalk. It suggests at least three **kinds** of data, such as optical, topographic, geological/spectral, atmospheric, geophysical, thermal, radiation and chemical. This is a suggestion, not a strict requirement that three distinct data classes be available; for a strong product we commit to three: optical, topographic, geology. Add atmospheric/rover photos only if real.

- Map selected science destinations and **why** astronauts would visit them.
- Supply a route or location-specific map with surface mobility constraints and explain uncertainty.
- Integrate multiple NASA missions: MRO CTX imagery/DTM, Perseverance photos/MEDA if added; USGS planetary geology contextualizes the area.
- Reference successful route visualization (Curiosity proposed Mount Sharp route) as design inspiration, not as a Jezero dataset.
- NASA Worldview is Earth-centric; use as UX inspiration rather than fake Mars data.
- Use historically accurate timestamps; do not call archived weather 'live'.

## 5. Scientific integrity requirements

- No actual astronaut safety guarantees; research prototype only.
- Route metrics must derive from a real named DEM; Earth map projection units may not be used as Mars distances.
- No assertion that 20 m imagery/resolution reveals human-scale rocks/holes/soil mechanics.
- Surface photo markers need actual rover location metadata. Otherwise tag `context only`.
- Science targets must have real reference/context or be explicitly hypothetical.
- Estimated oxygen/energy/suit performance are **assumed/simulated**; include parameters and caveats.
- Never substitute a fake demo screenshot or unlabeled synthetic GIS data for evidence of actual observations.
- Cite every external visual, code dependency, library, text quotation and dataset.

## 6. Judging (guide p. 10)

The five named categories are **Impact, Creativity, Validity, Relevance and Presentation**. Design the demo to show concrete observations, methodology and an original integrated workflow, not only flashy UI.

| Category | Evidence to provide |
|---|---|
| Impact | Clear benefit for a future hyperlocal Marswalk |
| Creativity | Return-aware feasibility + evidence trail + one adaptive recovery scenario |
| Validity | Real NASA data, correct coordinates, test fixtures, measured outputs, caveats |
| Relevance | Scientific target, integrated NASA layers, route, hazard/resource context |
| Presentation | Short and readable demo; accessible publicly; clear challenge and team |
